Chapter 6 of Applied Statistical Modelling for Ecologists, by Marc Kéry and Kenneth Kellner, considers the case of two predictors in a linear regression model. Traditionally this would be a t-test if variance is equal, or the Welch test if they are unequal variances.

6.2 Equal Variance

The simulated data in this chapter is wing lengths of Peregrine falcons and tiercels. In the first section we assume (and thus simulate) that the data has equal variance. In the previous chapter x was continuous, but here it is a categorical dummy variable (‘maleness’).

The base model is the same:

\(y_i = \alpha + \beta x_i + \epsilon_i\)

\(\epsilon_i \sim \mathcal{N}(0, \sigma^2)\)

Since x is categorical, we can split the linear part into group-specific means:

\(y_i = \begin{cases} \alpha + \beta\cdot 0 = \alpha & \text{if } x_i = 0 \\ \alpha + \beta\cdot 1 = \alpha + \beta & \text{if } x_i = 1 \end{cases}\)

‘Slope’ is thus the difference between the group means. Therefore this is effects parameterization.

An aside on rep()

In R, the rep() function is used to replicate the values in a vector. For example, rep(c(0,1), c(n1, n2)) creates a vector of n1 zeros followed by n2 ones. This is equivalent to the vcat(zeros(Int, n1), ones(Int, n2)) approach we used in Julia. There are different ways of reproducing rep()’s functionality in Julia, depending on the use case.

In the case we have here, where we are replicating 0s and 1s, the approach using vcat(zeros(Int, n1), ones(Int, n2)) is straightforward and efficient. For more general cases, we can use fill, like this:

```{julia}
n1 = 3
n2 = 2
x = vcat(fill(0, n1), fill(1, n2))
# Output: [0, 0, 0, 1, 1]

x_group = vcat(fill("Control", n1), fill("Treatment", n2))
# Output: ["Control", "Control", "Control", "Treatment", "Treatment"]
```

To replicate rep’s ability to take a vector of values and repeat each according to a vector of counts, we can do the following:

```{julia}
# General R-style rep function in 1 line
rep(vals, counts) = reduce(vcat, fill.(vals, counts))

# Usage:
x = rep([0, 1], [n1, n2])
# Output: [0, 0, 0, 1, 1]

x_multi = rep([10, 20, 30], [2, 1, 3])
# Output: [10, 10, 20, 30, 30, 30]
```

Here are some other cases:

R Syntax Julia
rep(x, each = n) repeat(x, inner = n)
rep(x, times = n) repeat(x, n)
rep(x, each = a, times = b) repeat(x, inner = a, outer = b)
rep(c(a,b), c(n1, n2)) vcat(fill(a, n1), fill(b, n2))
rep(x, length.out = n) repeat(x, ceil(Int, n / length(x)))[1:n]

6.2.5 Bayesian analysis

Since Turing is an HMC sampler we will refer to the Stan section for model code comparison, but the output is shown for JAGS in the book. As before, we use the Stan code’s prior of half-Cauchy for the standard deviation. Turing uses 1000 burn-in, so 2000 saved with 4 chains should match the number saved in JAGS.

using Turing, FlexiChains, MCMCDiagnosticTools

@model function model6_2_5(y, x)
    α ~ Normal(0, 100)
    β ~ Normal(0, 100)
    σ ~ truncated(Cauchy(0, 10); lower=0)

    μ = @. α + β * x
    y ~ arraydist(Normal.(μ, σ))

    # Return what you want to track, in this case the residuals. This is for method 2, below
    return y .- μ
end

model_turing25 = model6_2_5(y_obs.y, y_obs.x)
chains = sample(model_turing25, NUTS(), MCMCThreads(), 2000, 4; progress=false)

Then we calculate the residuals. There are two ways to do this. The first is quick, straightforward, and appropriate here, and uses matrix broadcasting; no need to add any tracked quantities to the model (no ‘return’). While we are about it, we also get the predictions.


# Calculate μ for all samples and all data points
# Data vectors are transposed to row vectors (1 x N)
# The result is an S x N matrix of predictions
μ_post = α_post .+ β_post .* y_obs.x'

# Calculate the residuals (S x N matrix)
# Each row is a posterior sample, each column is a data point
residuals_matrix = y_obs.y' .- μ_post

# If you want the mean residual for each observation:
mean_residuals = vec(mean(residuals_matrix, dims=1))

# Or the 95% credible intervals for the residuals:
using StatsBase
lower_ci = vec(mapslices(x -> percentile(x, 2.5), residuals_matrix, dims=1))
upper_ci = vec(mapslices(x -> percentile(x, 97.5), residuals_matrix, dims=1))

print("Mean residuals: ", first(mean_residuals, 5))

The second way, the more ‘Turing’ way, is using generated_quantities. This is less transparent, but much less complicated if we are dealing with hierarchical models. The return calculation we added to the model allows us to track, but they are not calculated during the run (so no slowdown), they are calculated when we call generated_quantities afterwards.

# This returns a matrix of arrays containing the residuals

# Because gen_residuals is an array of arrays (Chain length × Chains),
# you will usually want to flatten/format it. 
# Here is a quick way to stack it into a standard S x N matrix:
residuals_matrix = reduce(vcat, transpose.(vec(gen_residuals)))
mean_residuals = vec(mean(residuals_matrix, dims=1))

6.3 Comparing two groups with unequal variance

Here we consider that the variance in wingspan may differ between the two groups. This is important because assuming equal variance when it is not true can lead to incorrect inferences. The new model allows each group to have its own variance, typically called \(\sigma_{\text{group}}^2\).

\(y_i = \alpha + \beta x_i + \epsilon_i\)

\(y_i = \begin{cases} \epsilon_i \sim{Normal(0, \sigma_1^2)} & \text{if } x_i = 0 \text{ [females]} \\ \epsilon_i \sim{Normal(0, \sigma_2^2)} & \text{if } x_i = 1 \text{ [males]} \end{cases}\)

So now we have to estimate an additioal parameter for the variance of each group, namely \(\sigma_1^2\) for females and \(\sigma_2^2\) for males.

6.3.5 Bayesian analysis

As mentioned, the HypothesisTests.jl functions don’t have quite the same output. I’ll move straight to Bayesian analysis.

@model function model6_3_5(y1, y2)
    # priors
    μ1 ~ Normal(0, 100)
    μ2 ~ Normal(0, 100)
    σ1 ~ truncated(Cauchy(0, 10); lower=0)
    σ2 ~ truncated(Cauchy(0, 10); lower=0)

    # Likelihood
    y1 .~ Normal(μ1, σ1) # females
    y2 .~ Normal(μ2, σ2) # males

    delta := μ2 - μ1
end

Which matches very well. Note that there is a difference in the way the likelihood is written here compared with previous examples. Previously, we had something like

μ ~ @. α + β * x

y ~ arraydist(Normal.(μ, σ))

Here, μ is a vector of means, and arraydist then constructs the joint likelihood as the product of the individual Normal densities.

In the two groups case, however, we have two separate groups with their own means and standard deviations. Therefore, we can directly write the likelihood for each group using the element-wise broadcasting syntax .~ without needing to construct a vector of means. This simplifies the model and makes it more interpretable for the two-group comparison.

6.3.6 Do-it-yourself maximum likelihood estimation

using Distributions
using Optim

# Define the NLL function
# params is a vector: [mu1, mu2, sigma1, sigma2]
function nll(params, y1, y2)
    mu1 = params[1]
    mu2 = params[2]
    sigma1 = params[3]
    sigma2 = params[4]
    
    # Optimizers explore wildly; we must return Infinity if they guess 
    # a negative or zero standard deviation to reject that path.
    if sigma1 <= 0 || sigma2 <= 0
        return Inf
    end
    
    # logpdf.(distribution, data) calculates the log-likelihood for each data point
    # sum() adds them up for the whole vector
    ll_y1 = sum(logpdf.(Normal(mu1, sigma1), y1))
    ll_y2 = sum(logpdf.(Normal(mu2, sigma2), y2))
    
    # Return the negative log-likelihood
    return -(ll_y1 + ll_y2)
end
nll (generic function with 1 method)

Now we can optimize this negative log-likelihood function to find the maximum likelihood estimates for the parameters. As in previous chapters we need to wrap the parameters in an anonymous function for optim(). Same initial guesses as the book.

# 1. Set your initial guesses for [mu1, mu2, sigma1, sigma2]
initial_guesses = [50.0, 50.0, 1.0, 1.0]

# 2. Create a closure so the optimizer only sees a function of `p` (the parameters)
objective_function = p -> nll(p, y1_obs, y2_obs)

# 3. Run the optimization
# You can explicitly ask for NelderMead(), or let it default
result = optimize(objective_function, initial_guesses, NelderMead())

# 4. Extract your results
println(result)

# Get the exact maximum likelihood estimates
mle_estimates = Optim.minimizer(result)
println("MLE for mu1: ", mle_estimates[1])
println("MLE for mu2: ", mle_estimates[2])
println("MLE for sigma1: ", mle_estimates[3])

Efficiency Comparison

In the last section of each chapter I compare the efficiency of the HMC/NUTS model in Julia with the JAGs model in R. All run on a MacBook Pro with M5 Pro chip, 24GB RAM.

There are two models in this chapter; I just compare the second one. I ran the jagsUI model in RStudio and saved the MCMC metrics to a CSV file, which we will read into Julia for comparison. Here is the R code, added at the end of the 6.3.3 section:

```{r}
# Output metrics for comparison with Turing
compare.params = c("mu1", "mu2", "sigma1", "sigma2")

# Time the whole run (wall clock, includes adaptation + burnin)
elapsed <- system.time({
    fit <- jags(data     = dataList,
            inits        = inits,
            parameters.to.save = compare.params,  # keep this list IDENTICAL to Julia

            n.iter       = ni,
```

The Turing model is much faster, which is as expected. As the model becomes more complex, and more samples are saved, the discrepancy becomes greater, it seems. This isn’t the fastest it could be, because I use the := syntax to store delta; this calculates it during the sampling run and stores the results immediately in the chain, which is convenient. This is a simple calculation so not costly, but better is to use return delta = μ2 - μ1. This is not run during sampling, but only afterwards when you run generate_quantities(chains).

Note

In the Julia code I do not use GPU acceleration, but Turing.jl does support it. Since I’m on Apple Silicon, I could use Metal acceleration for certain computations (CUDA is also supported), which might further improve performance. I wouldn’t bother in this case, but if the dataset is > 100,000 or if it is a high-dimensional matrix model (spatial models, GLMMs, etc), I would experiment with hardware acceleration. Matrix multiplications scale significantly faster on GPU cores.
