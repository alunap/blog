We turn to Chapter 4 of Applied Statistical Modelling for Ecologists, by Marc Kéry and Kenneth Kellner. IN this chapter we turn to a comparison of different statistical modelling approaches for ecological data. The book considers jagsUI, NIMBLE, TMB, Stan, and Maximum Likelihood. I add Turing.jl to the mix, with a brief discussion of other Julia packages.

The Turing.jl model

This is the main point about using Julia for Bayesian statistics. Let’s build the same model in Turing.jl. Note that as this is running in a Quarto document I have not set chains=4 as I normally would. Also, with the latest version of Turing, the default chain type has changed, so we explicitly set it to Chains in the sampling call to maintain compatibility with the MCMCDiagnosticsTools function below, which are not yet updated to FlexiChains.VNChain format.

using Turing

@model function model_4_4(mass)
    # 1. Priors
    # Note: BUGS dnorm(0, 0.0001) uses precision τ = 0.0001, 
    # which corresponds to variance 10,000 or SD = 100 in Turing.
    pop_mean ~ Uniform(0, 5000)
    pop_sd ~ Uniform(1, 100)

    # Add derived quantity for variance if required
    pop_var = pop_sd^2
    # 3. Likelihood (Vectorized)
    mass .~ Normal(pop_mean, pop_sd)
end

# Sampling
model = model_4_4(y1000)
chains = sample(model, NUTS(), 10000; chain_type=Chains)

Keep in mind that this is a HMC/NUTS model, so equivalent to the Stan example. To me, at least, the model code is far more readable, and the steps needed to compile and run the model also short, simple, and easy to understand. More so than NIMBLE: no configure/build/compile/compile/run sequence, just define the model and sample. And the model itself has no declaring of types, no defined sections for params and data, and the code is Julia, so it has the full range of Julia functions available. Also, there is no likelihood loop, because it can do broadcasting as normal, so it is even shorter than the JAGS model code.

One thing to note is that, as it is Julia code, the order matters, unlike JAGS. You have to define variables before you can refer to them.

Logical tests

For jagsUI (section 4.4.2) the book shows how to do straightforward logical tests, such as mean(sims[,"pop.mean"] < 597). We can do a similar thing with Turing.

The direct vector extraction way

# Extract flattened vector of all posterior draws (e.g. 10,000 x 4 = 40,000 draws)
pop_mean_draws = vec(Array(chains[:pop_mean]))

# Calculate posterior probability P(pop_mean < 597)
prob = mean(pop_mean_draws .< 597)
0.0208

As a one-liner

# Direct one-liner
prob = mean(chains[:pop_mean] .< 597)
0.0208

Other options besides Turing

The Julia ecosystem is a lot less mature than R. Turing itself is mature and stable, but other packages for Bayesian modeling may not be as fully developed or as user-friendly as their R counterparts.

TuringGLM

I tried JuliaBUGS and TuringGLM as well, and could get neither to work. TuringGLM has just been archived, end of August 2026, in favour of newer packages. It would be the equivalent of brms. It is being replaced by TuringRegressions.jl and/or BayesianRegressionModels.jl, which I have not yet tried. There is also Soss.jl which seems to be a Julia interface to the Python library, so will not be considered here. I will try the other two packages and if successful, I will report my findings here.

JuliaBUGS

If TuringGLM is the equivalent of brms, then JuliaBUGS is the equivalent of rjags or jagsui, providing an interface to the JAGS modelling language from within Julia. It does not call the R programs, but runs on top of Turing.jl. This sounds great for someone coming from R. Even better, it refers to a subpackage in R which would allow R users to run their model in Julia. However, the documentation is messy and I could not get either this simple model to work nor the examples in the documentation. Therefore, I will not be considering JuliaBUGS further in this series.

Gibbs Sampler

It is a shame that there is no direct equivalent to a Gibbs sampler in Julia, as they do make handling of discrete variables such as N-Mixture or occupancy models much easier. There is a Gibbs sampler, but it seems to be for combining different samplers within a single framework. However, there is an argument to be made that marginalisation is the best approach.

I note that Turing does support Particle Gibbs, but I don’t think that is quite the same use case. They provide AbstractMCMC as a common interface for MCMC samplers, which allows for flexibility in choosing different sampling algorithms, and it would seem not too difficult to have a Gibbs sampler for common ecological use cases to be built using it. There is, after all, a Metropolis-Hastings sampler. I’ll look into that possibility.
