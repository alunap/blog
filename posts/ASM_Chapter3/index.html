About ASM

Applied Statistical Modelling for Ecologists (ASM) by Marc Kéry & Kenneth F. Kellner is a fantastic resource for quantitative ecologists looking to deepen their understanding of statistical modeling techniques. It is not as ‘advanced’ as Applied Hierarchical Modeling for Ecology vols 1 & 2 (AHM), or Integrated Population Models (IPM), but it provides a solid foundation for understanding and applying statistical models in ecological research. It takes a Rosetta Stone approach, with examples in JAGS, Stan, NIMBLE, TMB, and ‘MLE-DIY’. But, what statistical Rosetta Stone is complete without a Julia implementation? You could argue the same about a Python implementation, but although I commonly use Python for data engineering and Machine Learning tasks, I never use it for statistics, so I will leave that to someone else.

When I read for my BSc there was a course in statistics, and I enjoyed it because it was very practical. It was statistics that let me make sense of the data I collected and draw conclusions. Back then, it was all about using a cookbook, namely Biometry by Sokal & Rohlf. Inside the front and rear covers was a table, which you would consult to see, depending on number of variables and type of variables, which type of Null Hypothesis Significance Test (NHST) you should use: t-test, X-square, ANOVA, ANCOVA, etc. Each had its own table for looking up the significance level.

It was only when I started diving into Bayesian methods around 6 years ago that I realised these were pretty much all just variations of the same thing: linear models. What the ASM book emphasises is not only are the different frequentist methods related in this way (via GLM), but that Frequentist (Maximum Likelihood Estimation) and Bayesian methods are also related, via the likelihood function. This is the subject of Chapter 2, which I’ll write about later.

It is not my intention to repeat the explanations in ASM, but just to add Julia to the Rosetta stone approach, with some remarks where I was struck by something. Therefore, if you don’t have the book this section may be of little use to you. For those with the book, I give section numbers so that you can match up the Julia code with the corresponding sections in the book.

Of course, Julia has RCall, and anything done in the book can be done in a Julia program, combining the speed of Julia for data munging with the exact statistical capabilities of R. I enjoy working in R, but I also appreciate the performance and flexibility that Julia offers.

Distributions

This chapter starts a discussion of the common distributions, namely Gaussian, Binomial/Bernoulli, Poisson, and Uniform. Interestingly, not Exponential, Laplace, Beta, Gamma, or half-Cauchy. That makes me interested to see the Bayesian models later in the book, to see what priors they are using.

3.2.1 Gaussian Distribution

The chapter starts with the Gaussian, or Normal, distribution. This is determined by two parameters, the mean and the standard deviation. In Julia we can directly use Greek letters, not a romanised word.

n = 100_000
μ = 600
σ = 30

sample = rand(Normal(μ, σ), n)
histogram(sample, bins=60, normalize=:pdf)

The rest follow a similar pattern, but note that the way you get a random sample is different from R. There are no ‘r’, ’d’, ‘p’, or ’q’ functions as in R; instead, you use the rand function for sampling.

3.2.2 Uniform Distribution

The Uniform distribution is defined by two parameters which are the minimum and maximum values over which we want equal probability.

n = 100_000
a = lower_limit = 0
b = upper_limit = 10

sample = rand(Uniform(a, b), n)
histogram(sample, color = "grey", breaks=30)

3.2.3 Binomial Distribution

A Bernoulli distribution occurs when a binary event can occur with probabilty p, such as a coin toss. If there is a succesion of Bernoulli trials, each with the same probability of success, this is a Binomial distribution. In the book they graph proportions rather than frequencies, and I do the same here. Note the difference from Poisson. Although both deal with an integer, perhaps a count, in the Binomial case there is a strict upper limit. For example in capture-recapture you can’t recapture more than you captured in the first place (the upper limit is the number of trials).

n = 100_000
N = 16
p = 0.8

# Draw random numbers
samp = rand(Binomial(N, p), n)

# Calculate relative frequencies (Equivalent to table(sample)/n)
pm = proportionmap(samp)

# Extract and sort the keys and values for plotting
x_vals = sort(collect(keys(pm)))
y_vals = [pm[k] for k in x_vals]

# Plot them
bar(x_vals, y_vals,
    bar_width=0.4,          # Equivalent to lwd = 20 (adjust to taste)
    color=(:black),    
    linecolor=:transparent, # Removes borders to match R's flat lines
    xlims=(0, 16),
    ylabel="Probability",
    framestyle=:axes,       
    legend=false,
    xlabel="sample"
)

Here is a simpler approach; we don’t have to expose the proportions calculations as histogram() can normalise by itself

histogram(samp,
    normalize=:probability,
    bins=-0.5:1:16.5,       # Forces bins to center exactly on integers
    bar_width=0.4,
    color=(:black),
    linecolor=:transparent,
    xlims=(0, 16),
    ylabel="Probability",
    xlabel="sample",
    framestyle=:axes,
    legend=false
)

In the book they use R’s model.matrix() function to show the design matrix, which is very valuable for really understanding what is going on, and how categorical variables and continous variables can coexist in the same model framework. There isn’t a direct counterpart to that in Julia, so we make one. R’s matrices can have column labels, whereas Julia’s standard matrices do not, so we wrap the matrix in a DataFrame to retain the column names. The default DataFrame column names are of the form ‘reg:1’, ‘pop:2’, etc so we replace the ‘:’ with an empty string to make them match the R function output.

function design_matrix_df(formula, df)
    mf = ModelFrame(formula, df)
    mm = modelmatrix(mf) # shorthand for ModelMatrix(mf).m
    col_names = replace.(string.(coefnames(mf.f.rhs)), ": " => "")
    return DataFrame(mm, col_names)
end

The outputs are equivalent. In the effect parameterization, the intercept represents the mean of the reference group, whereas in the means parameterization, each coefficient represents the mean of the corresponding group. So in effect parameterisation the average mass of snakes in the ‘default’ region 1 is 65, and region 2 we see ‘35’. That 35 is the difference from region one, not the mass itself. In means parameterization, the average mass of snakes in region 1 is still 65, but in region 2 it is 100, which is 65 + 35.

Effect parameterization is best when you are interested in the differences between groups, and means parameterization is best when you are interested in the actual group means.

Much of this is very familiar to me, but the real eye opener has been seeing the design matrix for each example, and realising that for categorical variables the dummy variables act like an indicator function in maths. If it is 1 then the value of that term is the coefficient, and if it is 0, the term does not contribute to the linear predictor. It is so simple when you see it like that.
