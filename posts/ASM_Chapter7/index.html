7.2 Fixed-Effects Models

7.2.5 Bayesian analysis with Turing

Heretofore I have not used loops for the likelihood, as it is generally not necessary. In this case I show that you can translate the R code in a way that mirrors the R code more closely. In general you don’t need to do this, but if you plan to use predict() later (eg for a Prior Predictive Check), then that function can struggle with vectorised likelihoods.

using Turing

@model function fixed_effects(y, pop, nPops)
    # Parameters and Priors
    α ~ filldist(Normal(0, 100), nPops)  
    σ ~ truncated(Cauchy(0, 10); lower = 0) 
    
    # Likelihood: Use a for loop to allow predict() to simulate missing data
    for i in eachindex(y)
        y[i] ~ Normal(α[pop[i]], σ)
    end
    
    # Generated Quantities
    effe2 = α[2] - α[1]
    effe3 = α[3] - α[1]
    effe4 = α[4] - α[1]
    effe5 = α[5] - α[1]
    
    test1 = (effe2 + effe3) - (effe4 + effe5)
    test2 = effe5 - 2 * effe4
    
    return (; effe2, effe3, effe4, effe5, test1, test2)
end

model = fixed_effects(y, pop, nPops)
chain_fe = sample(model, NUTS(), MCMCThreads(), 3000, 4; progress=false)

7.2.6 DIY Maximum Likelihood Estimates

There are a couple of differences to keep in mind in using Julia rather than R.

  • Matrix Multiplication: In R, you would use %*% to multiply \(X\) and α. In Julia, the standard * operator performs true matrix multiplication automatically when the left operand is a Matrix and the right is a Vector.
  • Preventing Domain Errors: The line if σ <= 0.0 return Inf end is a critical Julia optimization pattern. Unlike R’s optim() which can sometimes suppress internal warnings, Distributions.jl will throw a hard error if you try to instantiate a Normal distribution with a negative standard deviation. Returning Inf cleanly tells Optim.jl to move away from that parameter space.
  • Anonymous Functions for Optimizers: R’s optim allows you to pass additional data arguments (like y and X) via the … argument. Optim.jl strictly expects a function of a single variable (the parameter vector). The syntax p -> NLL(p, y, X) creates a fast, on-the-fly closure that satisfies this requirement.
using Distributions
using Optim
using Statistics

# Define the Negative Log-Likelihood (NLL) function
function NLL(param, y, X)
    α = param[1:5]
    σ = param[6]
    
    # The optimizer will sometimes test negative values for sigma.
    # Returning Inf acts as a hard boundary to prevent domain errors.
    if σ <= 0.0
        return Inf
    end
    
    # Matrix multiplication: X (n x 5) * alpha (5 x 1) = mu (n x 1)
    μ = X * α
    
    # Calculate the negative sum of the log-likelihoods
    return -sum(logpdf.(Normal.(μ, σ), y))
end

# Build the design matrix (X)
# This creates an n x 5 matrix of zeros, then places a 1.0 in the column 
# corresponding to the population index for each observation.
n = length(y)
X = zeros(Float64, n, 5)
for i in 1:n
    X[i, pop[i]] = 1.0
end

# Set initial values for the optimizer
# A good starting point is the global mean of y for the alphas, and the global standard deviation for sigma
init_param = [fill(mean(y), 5); std(y)]

# Run the optimizer
# We use an anonymous function (p -> NLL(p, y, X)) to pass the data along with the parameters
result = optimize(p -> NLL(p, y, X), init_param, NelderMead())

# Extract the MLE estimates
mle_estimates = Optim.minimizer(result)

7.3 Random Effects

The main point of this chapter is highlighting the difference between fixed effects and random effects models in the context of hierarchical data. So let’s get into it.

  • Fixed effects (β parameters): These are the parameters we treat as constant across the population (or the specific contrasts we care about). We put priors directly on them. They represent the “average” or “overall” effect (e.g., global intercept, slope of a covariate like year or habitat).
  • Random effects (u or α parameters): These are group-specific deviations (e.g., site-specific intercepts, year-specific intercepts). We model them as coming from a common probability distribution (usually Normal(0, σ_group)), with hyperparameters (mean μ_group, usually 0 after centering, and variance σ_group²) that are themselves estimated. This induces partial pooling / shrinkage.

This is the key Bayesian hierarchical insight: random effects are parameters with their own priors that are estimated from the data, allowing us to borrow strength across groups while quantifying group-level variation. Random effects ‘soak up’ variance that would otherwise inflate the residual error, leading to more accurate estimates of both group-level and overall effects. Fixed effects, on the other hand, are treated as constant across groups and capture the overall mean trends in the data.

In code, we can see the difference in the parameters.

Fixed effects will be coded like β ~ Normal(0, 10) while random effects will be coded like α[group] ~ Normal(0, σ_group), with a hyperprior on the group-level standard deviation, e.g., σ_group ~ Exponential(1). The parameters of the distribution are not fixed quantities, they are defined on a separate line of code and shared.

7.3.5 Bayesian analysis with Turing

In the Stan code it uses truncated Cauchy for pop_means, but that causes issues with ForwardDiff in Julia, so we use a plain Normal instead. Since y is all positive, we get the same result. On first running I got a few divergent transitions, but changing the target acceptance rate in NUTS helped.

Because effe is a vector in Stan rather than separate scalars, returning NamedTuple(Symbol("effe[$i]") => effe[i] for i in 1:nPops) unpacks effe[i] through effe[nPops] into individual scalar fields. The generated_quantities output then drops straight into the FlexiChain conversion code from the fixed-effects model without modification.

@model function random_effects(y, pop, nPops)
    # Hyperpriors and variance components (constant bounds are safe for ForwardDiff)
    pop_grand_mean ~ truncated(Normal(0, 100), 0, Inf)
    pop_sd ~ truncated(Cauchy(0, 10), 0, Inf)
    residual_sd ~ truncated(Cauchy(0, 10), 0, Inf)

    # Random population means (plain Normal avoids the ForwardDiff Inf-bound NaN bug)
    pop_mean ~ filldist(Normal(pop_grand_mean, pop_sd), nPops)

    # Likelihood
    for i in eachindex(y)
        y[i] ~ Normal(pop_mean[pop[i]], residual_sd)
    end

    # Generated quantities
    effe = pop_mean .- pop_grand_mean
    return NamedTuple(Symbol("effe[$i]") => effe[i] for i in 1:nPops)
end

7.3.6 DIY maximum likelihood estimates

We finish with the MLE estimate for random effects. There are some significant differences here.

quadgk Return Signature

Unlike R’s integrate(…)$value, QuadGK.quadgk returns a 2-tuple (integral, estimated_error). Unpacking with L, _ = quadgk(...) grabs the integral directly.

Extracting the Hessian

Wrapping the objective with TwiceDifferentiable(NLL, inits) instructs Optim.jl to use finite differences for both the BFGS gradient steps and Optim.hessian!(td, mle_raw) at the converged solution, matching R’s optim(…, hessian = TRUE) behavior.

using QuadGK
using LinearAlgebra

function NLL(pars)
    pop_grand_mean = pars[1]
    pop_sd = exp(pars[2])
    sigma = exp(pars[3])

    LL = 0.0
    for i in 1:nPops
        # Subset data to population i
        ysub = y[pop .== i]

        # Numerically integrate out the random population effect r ~ Normal(0, pop_sd)
        L, _ = quadgk(-Inf, Inf) do r
            tot = 1.0
            for yj in ysub
                tot *= pdf(Normal(pop_grand_mean + r, sigma), yj)
            end
            tot *= pdf(Normal(0.0, pop_sd), r)
            return tot
        end

        # Guard against log(<= 0) during BFGS line searches
        if L <= 0.0
            return Inf
        end
        LL += log(L)
    end

    return -LL
end

# Minimize NLL using BFGS (matching R's optim defaults)
inits = [mean(y), 0.0, log(std(y))]
td = TwiceDifferentiable(NLL, inits)
out73_6 = optimize(td, inits, BFGS())

# Extract MLEs, Hessian, SEs, and 95% CIs (replicating ASMbook::get_MLE)
mle_raw = Optim.minimizer(out73_6)
H = Optim.hessian!(td, mle_raw)
se = sqrt.(diag(inv(H)))

mle_table = DataFrame(
    Parameter = ["pop.grand.mean", "log(pop.sd)", "log(residual.sd)"],
    MLE = round.(mle_raw, digits = 4),
    SE = round.(se, digits = 4),
    LCL = round.(mle_raw .- 1.96 .* se, digits = 4),
    UCL = round.(mle_raw .+ 1.96 .* se, digits = 4)
)
